## 背景

用户连续质疑原设计，每次都指向真问题。这份记录保留推理链，供后续封装专家时复用。

## 决策 1：密码找回 vs 密码重置

**结论**：找回在密码学上不成立，只做重置。

**理由**：加密产品承诺"连开发者也打不开"，而"能找回密码"要求有人知道你的密码，两者互斥。任何声称能找回密码的本地加密产品都在骗人或留后门。

**实现**：信封加密。DEK 是真钥匙，主密码/恢复密钥只负责包装它。忘记密码 = 用恢复密钥取 DEK + 重设密码，笔记内容不动。

---

## 决策 2：彻底删除 keyring 文件

**用户质疑**：为什么要单独维护一个可能单点故障的文件？密钥不能存在每篇笔记里吗？

**结论**：用户正确。删除 keyring.json。

**理由**：`.obsidian/` 被 Remotely Save 默认排除、重装插件会清空目录——这比磁盘损坏常见得多。把全部笔记的生死绑在一个隐藏文件上是错误的工程决策。

**实现**：`src/storage/note-keyring-store.ts` 从最高 epoch 的笔记读取密钥；`NoteKeyringStore.save()` 批量更新所有笔记的 `keys` 字段。插件目录不再有任何密钥文件。

**红利**：所有笔记共用同一把 DEK 的子密钥，所以**任意一篇带副本的笔记能恢复整个库**。

---

## 决策 3：改密码时更新副本 ≠ 重新加密内容

**用户质疑**：识别出被加密的文档，重置时改写它们就好了？

**结论**：用户正确。我此前把两件事混为一谈。

**实现**：拆两步——
1. 更新所有笔记的 `keys` 字段（PBKDF2 只跑一次，之后是 N 次小写入）
2. `data`/`salt`/`iv` 字节级原样拷贝

普通 Markdown 完全不碰。可中断续跑，已更新的自动跳过。

---

## 决策 4：加密文档用 `.sealed.md`

**用户要求**：加密文档必须被 Remotely Save 同步到；或者让加密文档不特殊，仍以 `.md` 结尾。

**调研结论**：
- Remotely Save 默认同步所有文件，只排除 `.` / `_` 开头 —— `.sealed` 理论可同步，但依赖配置且未实测
- `.md` 结尾是零兼容性风险的保证

**方案对比**：

| 方案 | 同步 | 隐私 | 风险 |
|---|---|---|---|
| A `.sealed` | 依赖同步工具对非 md 的处理 | 不进搜索索引 | 需实测 |
| **B `.sealed.md`** ✅ | 所有工具必定同步 | 密文进索引但无明文 | 需验证扩展名注册 |
| C `.md` + 标记 | 必定同步 | 索引密文 | 无法可靠接管打开，会自动保存覆盖 |

**选择**：B。用户确认接受密文被索引。

**关键技术细节**：`registerExtensions(["sealed.md"])` **是错的**。查 Excalidraw 源码确认，复合扩展名要注册**中间段**：

```ts
this.registerExtensions(["excalidraw"], VIEW_TYPE);  // 文件是 xxx.excalidraw.md
```

因此实现为 `registerExtensions([extensionToken()], ...)`，其中 `extensionToken()` 返回 `"sealed"`。

## 决策 5：不加"导出恢复包"

**用户质疑**：这不就是插件需要生成、需要离线保管的"恢复密钥"吗？

**结论**：用户正确，不加。

**理由**：
- 恢复密钥是高熵秘密本身，直接派生 KEK 解开 DEK
- 恢复包只是 `keys` 字段的副本，不含秘密，且已经在每篇笔记里随同步走了
- 它救不了任何恢复密钥救不了的场景
- 多一个需要保管的文件，与"减少单点"目标矛盾

**唯一需要离线保管的：恢复密钥。**

---

## 决策 6：回滚防护改为警告不阻断

**发现**：原实现检测 epoch 回退就抛错拒绝加载，这比回滚本身更糟——多设备同步冲突会让无辜用户被锁在外面。

**实现**：警告但照常加载；冲突文件另存备份；设置页持续显示警告。删除 keyring 文件后，独立文件的回滚概念已不存在，此机制随之移除。

---

## 决策 7：`tools/decrypt.html` 的定位

**结论**：独立应急工具，插件运行时**不使用**它。

**实现**：单文件、零依赖、零网络。粘贴任意一篇 `.sealed.md` 笔记即可解密——密钥就在笔记自己里面，不需要额外文件。有兼容性测试把真实 HTML 抽出来执行，验证与插件算法一致。

这个测试抓到过一个真实 bug：离线工具把 32 字节 DEK 当 UTF-8 解码，随机字节变成 U+FFFD，导致用恢复密钥解密 100% 失败。单元测试全绿也发现不了，只有真跑打包出去的 HTML 才能发现。
